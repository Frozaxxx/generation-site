# Архитектура и расширение до восьми направлений

## Принцип: один источник фактов

Утверждённая карточка компании (`CompanyProfile`, ревизия N) — единственный источник фактов. Все остальные результаты (сайт сейчас, документы и политики потом) строятся из **снимка** этой ревизии и не могут менять факты: имена, адреса, телефоны, характеристики продукта шаблоны берут из снимка напрямую, модель пишет только подачу и переводит.

```plain
параметры ─► генерация (LangGraph) ─► карточка r1 ─► правки ─► карточка r2 ─► утверждение
                                                                        │
                                       снимок r2 ──────────────────────┤
                                                                        ├─► сайт v1 (ru, kontor)
                                                                        ├─► сайт v2 (de, graphit)
                                                                        └─► (будущие направления)
```

- Правка карточки повышает ревизию и возвращает её в черновик. Уже собранные версии сайта остаются со своим снимком и помечаются как устаревшие (`stale`).
- Повторная сборка сайта не генерирует факты заново; тексты той же ревизии и языка переиспользуются бесплатно.
- Открытие сохранённых результатов (карточки, версии сайта, предпросмотр, архив) платных запросов не делает.

## Модули

| Модуль | Ответственность |
|---|---|
| `companies` | Каталог (страны, города, направления, масштабы), карточка, проверки фактов, генерация компании |
| `sites` | Темы, шаблон, тексты подачи и перевод, рендер, проверки сайта, версии, предпросмотр, архив |
| `llm` | Клиент OpenRouter, проверка ответов по схеме, повторы, стоимость, лимит операции |
| `jobs` | Фоновые операции с этапами и расходами, общие для всех направлений |

## Восемь направлений

| # | Направление | Что использует из карточки | Где будет жить |
|---|---|---|---|
| 1 | Оператор, история и команда | `brand`, `history`, `team` | есть: `companies` |
| 2 | Юридические документы | `brand.legal_name`, `contacts.address`, руководитель | новый модуль `legal` |
| 3 | Страновые реквизиты | `params.country`, `brand.legal_form`, город | расширение каталога `companies/domain/catalog` |
| 4 | Контакты | `contacts` | есть: `companies` |
| 5 | Продукт, сценарии и FAQ | `product`, `audience`, `faq` | есть: `companies` |
| 6 | Персональные данные и политики | `brand`, `contacts`, `product.inputs` (какие данные обрабатываются) | модуль `legal` |
| 7 | Безопасность | `product.process`, `product.delivery` | модуль `legal` |
| 8 | Клиенты, отзывы, кейсы, публикации | `audience.segments`, `product` | модуль `cases` |

Каждое новое направление устроено одинаково:

1. **Схема раздела** — dataclass в домене модуля, как `CompanyProfile`. Ссылки на факты карточки идут по путям (`contacts.address`), а не копиями.
2. **Граф генерации** на LangGraph получает снимок утверждённой карточки и пишет только свои тексты. Ответы модели проверяются pydantic-схемой с ограничениями (как `ConceptDraft.bounded`, `TranslationDraft.for_texts`).
3. **Проверки раздела** возвращают те же `Issue` (`code`, `severity`, `path`, `message`), что и проверки карточки, поэтому панель показывает их без доработок.
4. **Совместная проверка комплекта**: перед публикацией все разделы проверяются вместе с карточкой одной функцией, которая собирает `Issue` от каждого модуля (например, юрлицо и адрес в политике совпадают с карточкой и сайтом). Для сайта это уже делает `sites/application/checks.py`: факты сверяются по готовым HTML.
5. **Задачи** идут через общий `JobRunner`: этапы, прогресс, расходы и лимит операции достаются бесплатно.

Шаблон сайта получает новые страницы из тех же снимков: например, `privacy.html` из раздела 6 и `cases.html` из раздела 8, а проверка сайта начинает требовать их в навигации.

## Что сознательно упрощено для первого этапа

- SQLite и фоновые задачи внутри процесса вместо PostgreSQL и брокера: проект запускается одной командой. `JobContext` и обработчики не зависят от способа запуска, их можно перенести в taskiq-воркер без изменений.
- Одна страна (Германия) и два масштаба, как требует ТЗ. Новая страна — это `Country` в каталоге: города, правовые формы и блоки телефонных номеров для медиапроизводств.
- Регистрационные данные (номер в торговом реестре, налоговые номера) не генерируются: их нельзя выдумывать правдоподобно без риска совпадения с реальными компаниями.
